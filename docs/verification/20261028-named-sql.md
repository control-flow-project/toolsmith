# Named SQL bindings — 28 October 2026

All authored SQLite value bindings now use named placeholders and mappings,
including lexical/vector queries, archive operations, CLI composition, examples,
acceptance scripts and tests. The shared SQLite query function accepts an optional
mapping and rejects positional sequences. It does not translate positional SQL.
The stored schema, source identities, transaction boundaries and numerical
assertions are unchanged.

Verification on Linux/Python 3.13.15:

- Full local verification: 576 tests passed across 48 isolated modules; zero
  failed or skipped tests. Strict types passed for 129 source files, along with
  formatting, lint, wheel and sdist builds.
- Installed-package acceptance passed for base, HTTP and semantic installations,
  CLI/library parity and XML/JSONL/HTML/URL/ZIP/PDF/XLS primitives.
- Native vector tests retain independent ranking and SQLite membership oracles,
  transaction/rollback checks and extension-authorization checks.
- Regression checks reject authored positional SQL and verify repeated named
  parameters, null values, missing bindings and rejected sequence arguments.

These checks do not publish a package or change a running consumer. Consumers
must explicitly select the reviewed source revision.
